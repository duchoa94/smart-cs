# CLAUDE.md — Smart CS Codebase Guide

## Monorepo Layout

```
apps/api        Express 5 backend — REST API + Socket.IO server
apps/web        Next.js 15 admin dashboard (App Router)
apps/widget     Embeddable chat widget bundled with esbuild

packages/types      Zod schemas + z.infer<> TypeScript types (zero runtime except zod)
packages/db         Drizzle ORM schema, repositories, drizzle-kit migrations
packages/services   All backend logic: domain services, Redis cache, Milvus vector, AI/RAG
```

## Commands

```bash
pnpm install                  # install all workspace deps
pnpm dev                      # start all apps + watch packages
pnpm build                    # build everything (Turborepo)
pnpm typecheck                # type-check all packages and apps
pnpm lint                     # lint all

# Database (runs in @smart-cs/db)
pnpm db:generate              # generate SQL migrations from Drizzle schema
pnpm db:migrate               # apply pending migrations
pnpm db:studio                # open Drizzle Studio at localhost:4983
pnpm db:push                  # push schema directly (dev only, no migration file)

# Infrastructure
docker compose up -d          # start PostgreSQL, Redis, Milvus, MinIO, etcd
docker compose down           # stop all
```

## Package Rules

- `apps/web` and `apps/widget` must NEVER import `@smart-cs/db` or `@smart-cs/services`
- `apps/web` only imports `@smart-cs/types` (Zod schemas for form validation, TypeScript types)
- `@smart-cs/db` only imports `@smart-cs/types`
- `@smart-cs/services` imports both `@smart-cs/types` and `@smart-cs/db`
- `apps/api` imports `@smart-cs/services` for all business logic; never calls repos directly

## Key Files

| File | Purpose |
|---|---|
| `packages/types/src/schemas/*.schema.ts` | Zod schema definitions — single source of truth for all types |
| `packages/types/src/index.ts` | Exports schemas + `z.infer<>` derived types |
| `packages/db/src/schema/*.ts` | Drizzle table definitions (mirror the Zod schemas) |
| `packages/db/src/repositories/*.repo.ts` | Thin DB access layer — no business logic |
| `packages/services/src/config/env.ts` | Zod-validated env vars — exits process on invalid config |
| `packages/services/src/ai/rag/pipeline.ts` | Central RAG orchestrator (memory → embed → search → LLM) |
| `packages/services/src/vector/searcher.ts` | Milvus semantic search |
| `packages/services/src/cache/conv-memory.cache.ts` | Redis-backed conversation history |
| `apps/api/src/app.ts` | Express app factory |
| `apps/api/src/shared/errors.ts` | `AppError` class — all HTTP errors extend this |

## Adding a New Domain Feature

1. **Add Zod schema** in `packages/types/src/schemas/<domain>.schema.ts`
2. **Export** the schema and inferred type from `packages/types/src/index.ts`
3. **Add Drizzle table** in `packages/db/src/schema/<domain>.ts` + export from `packages/db/src/schema/index.ts`
4. **Add repository** in `packages/db/src/repositories/<domain>.repo.ts`
5. **Export repository** from `packages/db/src/index.ts`
6. **Add domain service** in `packages/services/src/<domain>/<domain>.service.ts`
7. **Export service** from `packages/services/src/index.ts`
8. **Add router + controller** in `apps/api/src/modules/<domain>/`
9. **Mount router** in `apps/api/src/app.ts`
10. **Run** `pnpm db:generate && pnpm db:migrate`

## Database

- ORM: Drizzle ORM (type-safe, no magic)
- All tables have `tenant_id` FK — every query must include it to enforce tenant isolation
- Repositories enforce `tenantId` on every find/update/delete
- Never write raw SQL unless for complex analytics — use Drizzle query builder
- Migrations live in `packages/db/migrations/` — generated by `drizzle-kit`, never edited manually

## Redis Key Naming

All keys are namespaced by tenant: `scs:{tenantId}:<type>:<id>`

```
scs:{tenantId}:conv_memory:{conversationId}   List, 20 messages, 2h TTL
scs:{tenantId}:agent:{agentId}:config         String, 10m TTL
scs:{tenantId}:session:{userId}:{sessionId}   String, 7d TTL
scs:ratelimit:{tenantId}:api:{userId}         ZSet, sliding window
scs:conv:{conversationId}:messages            Pub/Sub channel
scs:tenant:{tenantId}:handoffs                Pub/Sub channel
```

## Milvus Collections

One collection per tenant: `kb_chunks_{tenantIdNoHyphens}`

- SDK: `@zilliz/milvus2-sdk-node`
- Embedding dim: 1536 (OpenAI `text-embedding-3-small`)
- Index: IVF_FLAT (upgrade to HNSW at 100K+ vectors)
- Metric: Inner Product (IP) on normalized vectors
- Filter on search: `agent_id == "{agentId}" || agent_id == ""` (agent KB + shared KB)
- Min similarity score: 0.7 (below this = no relevant context)

## AI / RAG Pipeline (`packages/services/src/ai/rag/pipeline.ts`)

```
1. Fetch last 20 messages from Redis (conv_memory)
2. Embed user query → float[1536] via OpenAI
3. Semantic search in Milvus → top-5 chunks
4. Build system prompt: base prompt + KB context chunks
5. Call Claude with conversation history + user message
6. Estimate confidence from Milvus scores
7. Check handoff conditions (confidence < threshold, keywords, turn limit)
8. Push both messages to Redis conv_memory
9. Return PipelineOutput to caller
```

Handoff triggers (in `packages/services/src/ai/agents/handoff-detector.ts`):
- User requests human (`HANDOFF_KEYWORDS` list — includes Vietnamese phrases)
- AI confidence < `agent.handoffThreshold` (default 0.4)
- Conversation exceeds 10 AI turns

## WebSocket (Socket.IO)

Two namespaces on the same Socket.IO server:
- `/widget` — end users via embedded widget, auth by `{ agentId, tenantId, anonymousId }`
- `/dashboard` — staff users, auth by JWT in `handshake.auth.token`

Room naming: `conversation:{id}`, `tenant:{tenantId}:agents`

Redis adapter required for horizontal scaling (multiple API instances).

## Channel Integrations

**Zalo:** POST `/webhooks/zalo/:channelId` — verify HMAC-SHA256 with `channel.credentials.secretKey`, respond 200 immediately, process async
**WhatsApp:** POST `/webhooks/whatsapp/:channelId` — verify `X-Hub-Signature-256`, deduplicate via `externalMsgId`
**Web widget:** communicates exclusively via Socket.IO, no direct REST from widget to API

Channel `credentials` field in DB is AES-256-GCM encrypted (key from `ENCRYPTION_KEY` env var).

## Code Conventions

- No comments unless the WHY is non-obvious
- Zod schemas are the source of truth — derive TypeScript types via `z.infer<>`
- Drizzle row types (`AgentRow`) live in `@smart-cs/db`; domain types (`Agent`) live in `@smart-cs/types`
- Repositories return raw Drizzle row types; services map them to domain types using `Schema.parse()`
- `AppError` for all HTTP errors — never `throw new Error(...)` in controllers/services
- All Express route handlers are async — `express-async-errors` handles promise rejections

## Environment

Infrastructure via Docker Compose:
- PostgreSQL 16 → `localhost:5432`
- Redis 7 → `localhost:6379`
- Milvus 2.4 → `localhost:19530` (gRPC)
- MinIO (Milvus storage) → `localhost:9000`

Copy `.env.example` to `.env` before running anything.
`ENCRYPTION_KEY` must be exactly 64 hex characters (32 bytes for AES-256).
